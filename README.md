## What it does (the 7-stage broadcast pipeline)

| Stage | What MatchCast does | Where |
|---|---|---|
| **1. Ingest** | Replays ~2,100 synthetic events per match over WebSocket at 1x-20x | `backend/services/match_playback.py` |
| **2. Interpret** | xG, possession, rolling momentum, pressing, Attacking Channels (L/C/R), Set-Piece Threat, Keeper Goals Prevented | `backend/agents/data_agent.py`, `backend/services/story_finder.py` |
| **3. Discover** | Bundesliga-inspired Data Story Finder (Turning Points, Smash & Grab, Super-Sub, Finishing Woes, Metronome) | `backend/services/story_finder.py` |
| **4. Explain** | Tactical agent + three pundits (Host ─► Tactician · Passionate Fan · Analyst) debate discovered stories & moments | `backend/agents/` |
| **5. Render** | Timed machine-readable overlay JSON & live tactical facts drawn as broadcast lower-thirds & stats drawer | `backend/services/overlays.py`, `frontend/src/components/MatchStats.tsx` |
| **6. Visualise** | Coordinated 22-player collective pitch radar, continuous Sofascore-style player heatmaps with tactical third & flank accuracy, and rolling momentum wave graphs | `frontend/src/components/PitchVisualizer.tsx`, `frontend/src/components/MatchMomentumGraph.tsx` |
| **7. Personalise** | Language (EN / हिन्दी / ES), audience mode (fan / scout / broadcaster), favourite club, player focus, metric focus | `ProfileBar.tsx`, `POST /api/match/{id}/profile` |

### The Verifier (what makes it different)
Every pundit comment is scanned for checkable claims. Code (not an LLM) recomputes each value from the live match state:

- ✅ **verified**: the quoted xG / possession / momentum / score / pressure count matches the computed value
- ❌ **wrong**: it matches nothing in the data (the badge tells you the real value)
- ⚠️ **unverifiable**: a statistic no single match can support (e.g. *"in 84% of matches with this xG gap..."*)

The UI shows a badge per claim and a running **"Claims verified: X%"** counter. The built-in fallback pundits include a few such unverifiable lines (in broadcaster mode and in answers to questions), so the Verifier has real work to do.

## Quick start

**Prerequisites:** Python 3.11+, Node 18+. Azure OpenAI is optional (the app falls back to built-in commentary without credentials).

```bash
# 1. Backend (run from the repo root)
pip install -r backend/requirements.txt
cp backend/.env.example backend/.env      # optional: add Azure OpenAI credentials
python -m uvicorn backend.main:app --port 8000

# 2. Frontend (dev server on :5173)
cd frontend && npm install && npm run dev
```

Single-process alternative: `cd frontend && npm install && npm run build`, then `python launch.py` (serves the built UI on :8000).

Docker: `cp backend/.env.example backend/.env && docker compose up --build` (UI on :5173).

> Leave `DATA_DIR` unset unless you need to override it; it defaults to `data/matches`. If you set it, use an absolute path.

### Tests
```bash
pip install -r backend/requirements-dev.txt
python -m pytest -q
```
Covers the Data Story Finder (Turning points, Smash & grab, Finishing woes, Super-subs, Metronome), Attacking Channels, Keeper efficiency, Verifier (correct, wrong, unsupported claims), overlays (thresholds, languages, player focus, single metric), and data integrity (26/26 tests passing).

## Synthetic data (no real Premier League data is used)

`data/generate_matches.py` is a rule-based, seeded simulator with **fictional teams and players**. Three scripted storylines sit on top of a stochastic possession model, so scores are deterministic but play is not:

- **Total Domination**: **4-0** with high-pressing low-block dismantle (Thunderstrike United vs Aegis Port FC)
- **Apex United vs Titan City**: **1-4** on-demand unscripted match with clinical away finishing (middle card on dashboard)
- **The Great Comeback**: 0-2 down at half-time, wins **3-2** after a tactical switch (Synthetic City FC vs Metro Stars FC)

Each event carries position, outcome, xG, pressure and, for passes and shots, `distance_m`, `ball_speed_kmh` / `shot_speed_kmh` and `pass_difficulty`. Regenerate with `python data/generate_matches.py`.

Realism check of the shipped files (typical football ranges: ~10-15 shots per team, ~400-650 passes, low-to-mid-80s % pass accuracy):

| Match | Events | Shots (H / A) | Passes (H / A) | Pass acc. % (H / A) | xG (H / A) | Fouls | Cards (Y / R) |
|---|---|---|---|---|---|---|---|
| Total Domination (4-0) | 2,186 | 22 / 12 | 619 / 570 | 82 / 83 | 1.64 / 0.86 | 33 | 0 / 0 |
| Apex vs Titan (1-4) | 2,157 | 8 / 19 | 572 / 582 | 80 / 83 | 1.07 / 1.12 | 13 | 4 / 0 |
| The Comeback (3-2) | 2,119 | 10 / 17 | 592 / 622 | 85 / 84 | 0.69 / 1.16 | 34 | 0 / 0 |

Values are plausible, not calibrated to any real dataset. `data/matches/synthetic_derby.json` is a small hand-written sample; older stub files are in `data/archive/` and are not loaded.

## Architecture

```
generator → replay engine → Data Agent (deterministic metrics, key moments)
                                 ├─► Overlay engine (code only, personalised, EN/HI/ES) ─► WebSocket ─► broadcast overlays
                                 └─► Tactical Agent ─► Host ─► Tactician · Passion · Analyst
                                                                    └─► Verifier (recomputes every quoted number) ─► badges + "claims verified %"
```

| Component | Type |
|---|---|
| Data Agent, Overlay engine, Verifier | Deterministic code, no LLM |
| Tactical Agent, three Pundits, Host | Azure OpenAI (GPT-4o) with rule-based fallback when no credentials are set |
